# Monitor35

Turing 3.5인치 USB 화면용 Windows 데스크톱 모니터와 기본 배치 편집기.
현재 장치: USB35INCHIPSV2, 480×320 가로 화면. 기존 UsbMonitor 설치는 유지한다.

## 실행

현재 PC에는 .venv와 의존성이 준비되어 있다. **start.cmd**를 실행하면 미리보기가 열린다.
다른 환경은 Python 3.12( tkinter 포함)를 설치하고 **setup.cmd**를 실행한다.

1. 기존 UsbMonitor에서 편집 중인 테마를 저장하고 프로그램을 종료한다.
2. start.cmd 실행 후 **화면 연결**을 누른다. 초기화에 수 초 걸릴 수 있다.
3. 미리보기 항목을 드래그하거나 오른쪽 위치/글자 크기를 입력하고 적용한다.
4. **테마 저장**으로 유지한다. Ctrl+S 저장, Ctrl+Z 실행 취소. 닫을 때 미저장 변경은 자동 저장한다.
5. **연결 해제**로 포트를 반납한다. 마지막 화면은 LCD에 남는다.

화면이 거꾸로 보이면 오른쪽 **실제 화면 180° 회전**을 켠다. 실제 모니터 출력만 회전하며,
편집 미리보기와 드래그 방향은 항상 정방향을 유지한다. **테마 저장**으로 방향을 유지한다.

작업관리자 스타일의 CPU·메모리·디스크·네트워크 4분할 화면을 표시한다.

- CPU/GPU: 두 사용률을 큰 숫자로 함께 표시한다. 색 선은 CPU, 흰 선은 GPU다.
  클럭은 표시하지 않으며 CPU·GPU 온도를 22px로 표시한다.
- 메모리: 사용률(%)을 큰 대표값으로 표시하고, 사용 중/전체 용량은 보조 정보로 표시한다.
  하단에는 최근 60초 사용률 차트를 유지한다.
- 디스크: 전체 물리 디스크 읽기(R)·쓰기(W) 속도와 차트. 용량은 수집하거나 표시하지 않는다.
  디스크 I/O는 활성 시간(%)이 아닌 처리량이다.
- 네트워크: 선택한 어댑터의 수신(↓)·송신(↑) 속도. 색 선은 수신/읽기,
  흰 선은 송신/쓰기다. 네트워크 수신/송신과 디스크 R/W 속도·차트는 모두 MB/s(초당 백만 바이트)로 고정한다.
  자동 선택은 활성 어댑터 중 OS 누적량이 가장 큰 하나를 고르고 연결 중에는 유지한다.
  VPN/가상 어댑터가 선택되면 오른쪽에서 원하는 어댑터를 지정한다. 합산 중복은 없다.
- 모든 차트의 가로축은 60초다. CPU/메모리는 0~100%, I/O 차트는 표시된 자동 눈금을 쓴다.
  첫 샘플·카운터 초기화·절전 복귀 직후 속도는 `--`로 표시하며 다음 샘플에서 갱신한다.

주요 숫자는 기본 24px(CPU %와 같은 크기)이며 단위·설명만 작게 표시한다.
네 차트는 모두 기존 디스크 차트와 같은 크기로 카드 맨 아래에 배치한다.
디스크와 네트워크는 항목 이름 → 큰 속도 숫자와 오른쪽 MB/s → 최근 1분 사용량(1m, MB) → 차트 순서로 동일하게 배치한다.
카드 위치·각 카드의 숫자 크기·차트 색상·밝기 편집과 저장본 불러오기를 지원한다.
창의 X 또는 **백그라운드로** 버튼을 누르면 변경된 테마를 저장하고 트레이로 숨긴다.
연결된 화면의 갱신과 절전 복귀 처리는 계속된다. 트레이 아이콘을 클릭하거나
오른쪽 클릭 → **편집기 열기**로 복원한다. 종료하려면 트레이 메뉴 또는 편집기의 **완전히 종료**를 선택한다.
트레이 생성이나 저장에 실패하면 편집창을 유지한다. 숨겨진 상태에서 작업 오류가 발생하면 창을 다시 연다.

처음부터 백그라운드에서 장치에 연결하려면 `start.cmd --background --connect`를 실행한다.
이미 실행 중이면 트레이에서 기존 편집기를 열어 사용한다. 같은 장치에 여러 앱을 연결하지 않는다.
`--background`만 사용하면 전송 없이 미리보기로 실행된다. 로그인 자동 실행은 설정하지 않는다.

기존 버전 1 테마는 버전 2의 새 4분할 배치로 이전한다. 밝기·재연결 초기화·회전을 유지하며
기존 위치/색상/시계는 새 디자인으로 바뀐다. 첫 저장 시 원본은 `data/theme.v1.json`에 보관한다.
이전 앱으로 되돌릴 때는 앱 종료 후 이 파일을 `theme.json`으로 복사하면 된다.

## 자동 복구

- 절전 진입 시 화면 끄기 명령을 보내고 포트를 닫는다. 복귀 전에는 갱신하지 않는다.
- Windows 절전 복귀 이벤트와 실행 시간 공백을 감지한다.
- USB 오류 시 1~15초 간격으로 장치를 다시 탐색한다. COM4를 고정하지 않는다.
- 재연결 시 초기화·방향·밝기를 적용하고 화면 전체를 다시 보낸다.
- 정상 상태에서는 변경 영역만 보내고 30초마다 전체 화면을 갱신한다.
- 화면 아래 연결 상태·전송 수·실패 수·최근 전송 시간을 표시한다.

COM 포트 액세스 거부는 보통 다른 프로그램의 점유를 뜻한다. UsbMonitor와 동시에 연결하지 않는다.
별도 보드 모델에서 초기화 후 연결되지 않으면 **재연결 시 장치 초기화**를 해제하고 다시 연결한다.
USB 재삽입이 필요한 펌웨어 고장까지 소프트웨어로 복구된다고 보장하지 않는다.

## 진단 명령

```powershell
.\.venv\Scripts\python.exe -m monitor35 --devices
.\.venv\Scripts\python.exe -m monitor35 --smoke 3 --data-dir .tmp/preview
.\.venv\Scripts\python.exe -m monitor35 --connect --smoke 30 --data-dir .tmp/device
```

--smoke는 정상 종료 시 0, worker 오류 또는 마지막 실기기 전송 실패 시 1을 반환한다.
실기기 smoke 성공은 전송 완료 기준이며, 물리 화면 출력과 실제 절전·복귀 검증은 별도다.
테마: data/theme.json. 로그: data/monitor.jsonl. --data-dir로 분리할 수 있다.
로그는 로컬에만 기록되고 1MB 단위로 회전한다. 잘못된 테마는 덮어쓰지 않는다.

## 현재 범위와 제한

GPU는 NVIDIA 드라이버의 nvidia-smi가 있는 첫 NVIDIA GPU를 읽는다. 현재 PC의 RTX 4070 SUPER에서
사용률·온도를 확인했다. 조회 제한은 0.7초이며 실패 시 값을 --로 표시하고 15초 후 재시도한다.
AMD/Intel GPU 센서는 지원하지 않는다.
CPU 온도는 LibreHardwareMonitor 0.9.6과 PawnIO 드라이버가 필요하다. `setup-temperature.ps1`은
해시를 확인한 센서 라이브러리만 .venv/hardware에 준비하며 드라이버를 자동 설치하지 않는다.
PawnIO 설치에는 별도 관리자 승인이 필요하다. 필요하면 앱도 관리자 권한으로 실행한다.
CPU package/Tctl/Tdie 센서만 사용하고, 준비되지 않았거나 5초 이상 갱신이 없으면 --°C로 표시한다.
배경 이미지, 세로 화면, 원본 .data 테마 가져오기, 트레이 및 자동 실행은 아직 없다.
실제 LCD ACK가 없는 장치이므로 전송 성공 수치만으로 화면 갱신을 확정할 수 없다.

## 출처

장치 프로토콜은 [smartscreen-driver](https://github.com/hchargois/smartscreen-driver) 0.2.3을 사용한다.
원 프로젝트는 [turing-smart-screen-python](https://github.com/mathoudebine/turing-smart-screen-python)이다.
GPL-3.0-or-later. [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) 참고.

시스템 트레이(작업 표시줄의 숨겨진 아이콘 영역)에서는 남색 바탕의 청록색 모니터 아이콘으로 표시된다. 아이콘의 Windows 내 배치는 사용자 작업 표시줄 설정을 따른다. 창 제목 표시줄에도 같은 아이콘을 사용한다. 바로가기용 아이콘은 `src/monitor35/assets/monitor35.ico`에 있다.

동일 Windows 세션에서는 Monitor35를 하나만 실행한다. 다시 실행하면 새 프로세스는 종료되고 기존 편집창이 열린다(트레이 숨김/최소화 포함). 기존 연결과 편집 내용은 유지하며 두 번째 실행의 옵션으로 설정을 덮어쓰지 않는다. 이 기능이 없는 이전 버전은 업데이트 후 한 번 완전히 종료하고 다시 실행해야 한다.

1m 사용량은 최근 60초 측정 구간을 합산한다. 시작 후 1분 미만은 현재까지 측정분이며 수집 공백은 제외한다. 경계에 걸친 샘플은 해당 구간 평균 속도로 비례 계산한다.
